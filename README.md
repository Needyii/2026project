# 2026project

景区客流与服务调度项目 —— 青麓景区「入口排队与园内空区」问题的业务需求发现与流程梳理。

## 项目背景

节假日入口等待 55 分钟（目标 30 分钟），入口客流高但部分园区空闲，引导员看不到实时区域分布。管理层希望用 AI 改善客流调度，但尚未确定优先环节、验收标准和权限边界。

## 关键需求（待验证）

| 编号 | 需求 | 优先级 |
|------|------|--------|
| REQ-1 | 区域分布可见性缺口（入口拥堵与园内空闲并存） | P0 |
| REQ-2 | 交接"仅发送消息不算完成"的确认机制缺失 | P0 |
| REQ-3 | 安全事件与限流疏散必须保留人工指挥与签核 | P0 |
| REQ-4 | 数据新鲜度与接口降级规则先于调度建议落地 | P1 |
| REQ-5 | 试点指标口径需固定分母与排除规则 | P1 |
| REQ-6 | 反馈闭环需绑定业务编号与资料版本 | P2 |

## 验收硬指标

- 两个入口试点，计数误差低于 5%
- 安全事件及时转人工；限流疏散不自动实施
- 入口等待 55 分钟 → 30 分钟；局部拥挤告警提前 10 分钟

> 注：需求为基于合成场景访谈的待验证假设，调查覆盖 23/36，详见需求发现报告。
